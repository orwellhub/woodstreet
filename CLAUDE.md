# Wood Street Indoor Market

A static brochure site. Plain HTML generated by `tools/build.mjs` from
`data/shops.json`, deployed to Hostinger by pushing to the deployment branch.
No backend, no database, no accounts, no customer data.

Read `README.md` before changing anything. The short version: never edit the
generated `.html` files, change the generator or the data and run
`node tools/build.mjs`.

## Security baseline (applies to every change)

Adapted to this stack. Several of the usual rules do not apply here because
there is no server, no database and no login, and that is worth keeping true.

1. **The output is the product.** Every page is public and permanent. Nothing
   goes into `data/shops.json` or the generator that should not be world
   readable: no rents, no deposits, no owner or tenant names, no private phone
   numbers. The build refuses to finish if it finds a price or those words.
2. **Escape everything that comes from the data file.** Text goes through
   `esc()`. JSON embedded in a page goes through `jsonld()`, never bare
   `JSON.stringify`, or a shop name can close the script tag and inject HTML.
3. **Check schemes, not just characters.** Anything that becomes an `href` or
   `src` goes through `safeUrl`, `safeEmail` or `safeImage`. Links are https
   only; images must sit under `uploads/`. Escaping alone does not stop
   `javascript:`.
4. **No inline scripts and no inline event handlers.** The Content Security
   Policy allows `script-src 'self'` with no `unsafe-inline`, so an inline
   `<script>` or `onclick` silently will not run. Put behaviour in
   `assets/site.js`. Structured data in `application/ld+json` is fine.
5. **Any new third party breaks the CSP until you add it.** A font, a map
   embed, an analytics script or a new form endpoint needs its host adding to
   the policy in `.htaccess`. Prefer self-hosting; the fonts already are.
6. **Security headers live in `.htaccess`**, because a static site on shared
   hosting has nowhere else to set them. Do not remove HSTS,
   `X-Frame-Options`, the CSP, `X-Content-Type-Options`, `Referrer-Policy` or
   `Permissions-Policy`. Verify on the live response after deploying, not in
   the file.
7. **Nothing but the site is served.** The generator, the data, the archive,
   the audit folder, the README and dotfiles are blocked in `.htaccess`.
   `/.well-known/` is the deliberate exception. If you add a folder that
   should not be public, block it in the same place.
8. **No secrets, ever.** There are none today and there is no reason to add
   any. The contact form posts to a third party from the browser, so anything
   in the page is public by definition. If a feature ever needs a key, it
   needs a server, and that is a bigger conversation than one commit.
9. **Forms.** The contact form goes through FormSubmit with its captcha on and
   a honeypot field. Keep both. Never put a CRM or automation webhook URL in
   the page; anyone can then post to it directly.
10. **Accessibility is part of done.** Contrast at AA, real spaces between
    elements for screen readers, one `h1`, headings in order, `rel="noopener"`
    on every `target="_blank"`.
11. **Say what is true.** No invented shop details, opening hours, history or
    testimonials. If a photo or description is missing, the page says so. The
    policies page describes what has actually been tested.
12. **Before calling anything done:** `node --test tools/test.mjs`, then
    `node tools/build.mjs` and commit the regenerated pages. A security change
    ships with a test in `tools/test.mjs` that fails without it.

## Checks

    node --test tools/test.mjs     # regression tests
    node tools/build.mjs           # regenerate every page
    node tools/audit.mjs           # CSP and accessibility sweep (needs playwright + axe-core)

CI runs the first two on every push, and fails if the committed HTML does not
match a fresh build.
